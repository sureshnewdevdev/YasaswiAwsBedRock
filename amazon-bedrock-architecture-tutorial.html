01 / Foundation

What Amazon Bedrock does

Amazon Bedrock is the managed AI layer between your application and a foundation model. Your application can send a prompt directly to a model or use Bedrock Knowledge Bases to retrieve relevant passages from your documents before generating an answer.

Direct inference

Ask “Summarize this incident report” and send the report text in the request. The application already has the context.

Retrieval-augmented generation

Ask “What is the approval process for production access?” Bedrock searches an indexed policy collection and passes relevant excerpts to a generation model.

RAG supplies evidence at query time. Updating the policy generally means updating and syncing the data source. The foundation model’s weights stay the same.

02 / Architecture

Application, Bedrock and storage

The backend’s IAM role authorizes API calls. A separate Knowledge Base service role can access its source, embedding model and vector store as required by the configuration. Guardrails apply configured content policies. CloudWatch supports operational monitoring.

BoundaryResponsibility
ApplicationAuthenticate the user, enforce application permissions, build messages, call APIs and display citations.
BedrockRun model inference and, for the selected Knowledge Base path, orchestrate ingestion, retrieval and generation.
AWS resourcesS3 holds source documents. A vector store indexes searchable content. IAM controls access. CloudWatch records configured telemetry.

04 / Runtime

Direct model inference data flow

  1. User submits a task, such as summarizing a pasted incident report.
  2. Backend sends the model ID or profile, user message and any system instructions or conversation history to Converse.
  3. Bedrock invokes the model and returns the generated response. The backend displays it to the user.
From → ToPayload
User → applicationTask and report text.
Application → Bedrockmessages, modelId, optional system instructions, inference settings.
Bedrock → applicationMessage content, stop reason, usage, and runtime metrics when returned.

Converse / ConverseStream

Use a shared messages interface for supported models. Streaming lets a UI display text as it arrives.

InvokeModel

Use the model-specific request and response schema when the use case or model requires it, such as a text embedding invocation.

For a multi-turn direct chat, retain and resend the history your application wants the model to see. Limit the amount of history to control context size and cost.

06 / Retrieval and grounding

RAG query data flow

In the policy assistant, an employee asks “What is the approval process for production access?” The approved policy file was indexed during ingestion.

  1. Retrieve. Search the index for the most relevant chunks. Search may be semantic or hybrid depending on configuration. Metadata filters can narrow eligible documents.
  2. Ground. Provide the question and selected evidence to the generation model.
  3. Respond. Return generated text and any associated citations. Validate whether the cited passage actually supports the claim.
Choose the API for your Knowledge Base type. Use RetrieveAndGenerate with the custom vector-store path shown here. Fully managed Knowledge Bases use Retrieve or AgenticRetrieveStream. You can also call Retrieve and pass the returned passages to Converse yourself, using the retrieval options supported by your KB type.

07 / Lab setup

Prepare the AWS console and local Python

1. Pick a Region and verify model access

Open the Amazon Bedrock console. Select a Region that supports your chat model, Knowledge Base type and vector store. In Model catalog, open a chat model and record its model ID or supported inference profile ID or ARN. Follow the access prerequisites for that model. Some third-party models have Marketplace or first-use requirements.

2. Test the model in the playground

Open the chat playground, select your model and paste this prompt: “Summarize in one line: The staging API was unavailable for 15 minutes due to an expired certificate. The team rotated the certificate and restored service.” Look for a one-line summary containing the cause and fix.

3. Prepare a terminal

On Windows, use PowerShell with the AWS CLI and Python installed. Use an authorized AWS profile with temporary credentials. If your organization uses IAM Identity Center, run its login command first.

aws sso login --profile training
aws sts get-caller-identity --profile training
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade boto3
$env:AWS_PROFILE = "training"
$env:AWS_DEFAULT_REGION = "replace-with-your-region"
$env:BEDROCK_MODEL_ID = "replace-with-model-id-or-profile"

Change training to your configured profile. Skip the SSO command if you already authenticate through another configured profile. On macOS or Linux, create the environment with python3 -m venv .venv, use ./.venv/bin/python, and set variables with export NAME="value".

08 / Python lab

Call Bedrock Runtime with Converse

Save this code as infer.py. The SDK uses the profile and Region configured in the previous section.

import os
import boto3

runtime = boto3.client("bedrock-runtime")
result = runtime.converse(
    modelId=os.environ["BEDROCK_MODEL_ID"],
    system=[{"text": "Summarize the report in one sentence."}],
    messages=[{
        "role": "user",
        "content": [{"text": (
            "The staging API was unavailable for 15 minutes due to an "
            "expired certificate. The team rotated it and restored service."
        )}],
    }],
    inferenceConfig={"maxTokens": 150, "temperature": 0.2},
)
for block in result["output"]["message"]["content"]:
    if "text" in block:
        print(block["text"])
print("Usage:", result.get("usage", {}))

.\.venv\Scripts\python.exe infer.py

Expected observation. The response describes the expired certificate and restored service. Exact wording and token usage vary. Change the system instruction to request two bullet points and compare the output.

FieldPurpose
modelIdSelects the configured model or supported inference profile.
system and messagesSeparate task guidance from user and assistant turns.
inferenceConfigLimits generated tokens and sets sampling behaviour for the selected model.
output.message.contentContains typed content blocks. This lab displays only text blocks.

If the selected model rejects an optional setting, check its supported parameters and retry with a smaller request.

09 / RAG lab

Build and query the policy Knowledge Base

1. Create a sample source

In S3, create a private lab bucket in your selected Region. Save this content as production-access.txt and upload it under policies/.

Production Access Policy
Employees open a ticket in the Service Desk portal.
The employee's manager approves the business justification.
The platform operations team approves the requested access level.
Grant access for a maximum of 24 hours unless a separate exception is approved.

2. Create and sync a vector-store Knowledge Base

  1. In the Bedrock console, open Knowledge bases. Choose the creation option for a Knowledge Base with a vector store.
  2. Choose an existing authorized service role or create a dedicated role. Select Amazon S3 as the data source and enter your bucket and policies/ prefix.
  3. Choose a supported text embedding model and vector-store configuration. Use an eligible quick-create store if the account and Region support it. Review the storage costs and permissions before creating resources.
  4. Open the Knowledge Base’s data source and choose Sync. Wait for completion and review failed-document counts.
  5. In the Knowledge Base test panel, query the production-access question. Check the retrieved passages or generated answer and citations.

3. Run retrieval and generation from Python

Set the Knowledge Base ID from the console and the generation model or supported inference profile ARN. The ARN is used by this API’s modelArn field.

$env:BEDROCK_KB_ID = "replace-with-your-kb-id"
$env:BEDROCK_GENERATION_ARN = "replace-with-model-or-profile-arn"

Save as rag.py. Inspect Retrieve results before generating an answer. This script intentionally uses RetrieveAndGenerate only with the custom vector-store Knowledge Base.

import os
import boto3

kb = boto3.client("bedrock-agent-runtime")
kb_id = os.environ["BEDROCK_KB_ID"]
question = "What is the approval process for production access?"

retrieved = kb.retrieve(
    knowledgeBaseId=kb_id,
    retrievalQuery={"text": question},
)
for item in retrieved.get("retrievalResults", []):
    print("Passage:", item.get("content", {}).get("text", ""))
    print("Location:", item.get("location", {}))

response = kb.retrieve_and_generate(
    input={"text": question},
    retrieveAndGenerateConfiguration={
        "type": "KNOWLEDGE_BASE",
        "knowledgeBaseConfiguration": {
            "knowledgeBaseId": kb_id,
            "modelArn": os.environ["BEDROCK_GENERATION_ARN"],
            "retrievalConfiguration": {
                "vectorSearchConfiguration": {"numberOfResults": 3}
            },
        },
    },
)
print("Answer:", response["output"]["text"])
sources = set()
for citation in response.get("citations", []):
    for ref in citation.get("retrievedReferences", []):
        uri = ref.get("location", {}).get("s3Location", {}).get("uri")
        if uri:
            sources.add(uri)
for uri in sorted(sources):
    print("Source:", uri)

.\.venv\Scripts\python.exe rag.py

Expected observation. The answer should cite the policy and identify the Service Desk ticket, manager approval and platform operations approval. Ask a question unrelated to the document and check whether the system can recognize missing evidence.

Managed Knowledge Base variation. Keep the Retrieve portion and use the returned text as labeled evidence in the Converse prompt. Preserve each passage’s source location in your application so you can show it beside the answer. For managed agentic retrieval, use AgenticRetrieveStream according to its supported workflow.

11 / Advanced architecture

Where Strands Agents and AgentCore fit

A policy Q&A assistant can use Bedrock directly. If you extend it to check ticket status or take other actions, a framework such as Strands Agents can run the agent logic, while Bedrock AgentCore provides deployment and operational capabilities.

ComponentResponsibilityExample in this use case
Strands AgentsSDK and framework for implementing the agent loop and tools.Choose between searching the policy and calling a ticket status tool.
AgentCore RuntimeHosts the agent application with session isolation.Deploy the Python agent and invoke it from the backend.
AgentCore GatewayExposes configured tools to agents through MCP.Expose a read-only get_ticket_status tool.
AgentCore IdentitySupports workload identity and authorized access to downstream systems.Let the agent use authorized credentials for a ticketing API.
AgentCore MemoryStores and retrieves conversation or longer-lived context for the agent.Recall the current ticket reference within the intended session scope.
AgentCore PolicyEnforces rules for supported Gateway tool calls.Permit ticket status reads within the caller’s authorization.
AgentCore ObservabilitySurfaces traces, metrics and logs with applicable instrumentation and configuration.Compare model, retrieval and tool latency for a single request.

Design exercise. Draw the flow from user to agent, then split it into a policy-retrieval branch and a ticket-status branch. Identify which identity authorizes each branch and what happens if the tool times out.

12 / Production checklist

IAM, observability, costs and troubleshooting

IAM and application access

Grant the backend only the model and Knowledge Base actions it needs. Grant the Knowledge Base role access only to its authorized data source, embedding model and vector store. Keep user-level access checks in the application or supported retrieval access controls.

CloudWatch and logging

Track latency, failures, throttles and usage. Enable model invocation logging to CloudWatch Logs or S3 only when appropriate for the supported API and payload. Control log access and retention.

Cost control

Review model inference, embeddings, vector-store capacity and optional logging or evaluation costs. Limit output tokens and set a budget alert. Avoid putting real policies into a shared training account.

Cleanup

Delete the lab Knowledge Base and separately remove any lab-only vector store, S3 objects or buckets, log destinations and IAM resources that you created. Confirm resource dependencies before deletion.

SymptomWhat to check
AccessDeniedExceptionCaller identity, Region, permissions, organization policies, model access and service role scope.
ValidationExceptionModel ID versus ARN, inference profile requirement, model capability, Knowledge Base type and request shape.
Retrieval is emptyData source prefix, sync result, parser output, source filters and supported index configuration.
Wrong or unsupported answerRead the raw chunks, compare against the document, improve chunk boundaries or search settings, and test an explicit abstention rule.
ThrottlingCheck service quotas, use bounded retries with backoff and jitter, and control request concurrency.

13 / Practice

Interview questions and timed review

What is the difference between inference and retrieval?

Inference runs a model on supplied inputs. Retrieval finds source passages to add as context before generation.

What is the difference between an embedding model and a chat model?

An embedding model encodes data as vectors for similarity search. A chat model produces a response from instructions, messages and supplied context.

Why use two IAM roles in the reference architecture?

The backend role controls which APIs the application may call. The Knowledge Base service role controls its access to data sources, models and storage.

How would you diagnose an unsupported RAG answer?

Call Retrieve, inspect the chunks and source locations, and compare them with the claim. Verify ingestion, chunking, access filters and ranking before tuning the generation prompt.

How do Bedrock Runtime and AgentCore Runtime differ?

Bedrock Runtime invokes models. AgentCore Runtime hosts an agent application that can call models, retrieval and tools.

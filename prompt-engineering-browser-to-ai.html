01 · Learning outcomes

By the end, learners can distinguish an input event from an HTTP request, interpret a 200 response, explain what an API key does, and trace how a grounded answer selects and cites evidence.

Opening question “I press a key and see a 200 in DevTools. What did the server receive?” Ask students to propose a test before showing them the answer.

Use a harmless marker such as rag-demo-42. All policy documents and model outputs in the classroom lab are fictional.

02 · What happens when you type?

A keyboard event describes a key action. The input event fires when the user edits the field. Paste and deletion can also change the input, and an input method editor (IME) can compose text across several keystrokes. JavaScript decides whether any of these events trigger a network operation. MDN input event

Possible app behaviorWhen it can sendExample payload
Submit-only chatOn Send or a configured keyboard shortcut{"prompt":"Explain RAG"}
Draft syncAfter each edit or after a pause{"draft":"Explain RA"}
Activity eventOn an edit, focus, or timer{"event":"composer_edit"}
Autocomplete or live checksAs the product chooses, often after a pause{"prefix":"Expl"}
Unrelated background workOn a timer or another app eventHeartbeat or an account refresh

Autosaving a draft can transmit prompt text before Send. A feature can also perform computation before Send, depending on the implementation. Establish either claim from the observed content and supporting evidence. Product behavior can vary by feature, version, and session.

03 · End-to-end request and response flow

This is an illustrative architecture for a custom chat app. The public developer APIs are examples of the backend-to-provider hop. ChatGPT and Gemini web apps can use their own interfaces.

While composing

Edit text box→Browser input handler→App decides whether to send

Depending on the mode, the draft stays in the page, the browser sends an activity event, or it sends draft content immediately or after a pause.

On Send

Browser submits prompt→App backend→Model API

The backend can assemble instructions, conversation context and retrieved passages. It authenticates its model API call with server-held credentials.

On response

Model generates output→App backend relays output→Browser renders answer

The model processes the supplied context and generates output tokens. One request can deliver many output chunks over a stream. Chunk boundaries can differ from token or word boundaries. In the OpenAI Responses API, response.output_text.delta represents incremental text and response.completed signals completion. OpenAI streaming guide

04 · HTTP 200, the payload, and the API key

HTTP status

200 OK says the server reports success for that HTTP request. For a streaming endpoint, inspect stream events to see whether generation actually finished. MDN HTTP 200

Request payload

The request body can carry a JSON field like prompt or draft. A query string or WebSocket message can also carry data in other designs.

Browser session

The browser may authenticate to the app using a login session or other app-issued credential. That mechanism belongs to the app-to-browser relationship.

Provider API key

An API key authenticates the request to the provider. It is a secret credential. Keep long-lived provider keys on the backend. OpenAI API authentication

Example backend-to-provider request

This annotated HTTP example uses placeholders. The Authorization header carries the credential, and the JSON body carries the input and generation settings.

POST /v1/responses HTTP/1.1
Host: api.openai.com
Authorization: Bearer <SERVER_SIDE_SECRET>
Content-Type: application/json

{
  "model": "<MODEL_ID_AVAILABLE_TO_YOUR_PROJECT>",
  "instructions": "Explain concepts for first-time learners.",
  "input": "Explain RAG in one paragraph.",
  "stream": true
}

Gemini’s developer API also documents separate generate and stream operations. Its request schema uses contents. OpenAI Responses request format · Gemini generate content reference

05 · Observe a chat app in Chrome DevTools

  1. Open a fresh chat and use test text only. Open DevTools with F12 or Ctrl+Shift+I on Windows, then select Network.
  2. Clear the recording. Observe 5 seconds with no typing to establish which requests already occur. Enable Preserve log if the test involves a navigation.
  3. Type rag-demo-42 slowly without sending. Record how many new rows appear and their timing. Repeat with rapid typing and pause for a second. If you see several rows per edit, inspect them separately.
  4. Start with Fetch/XHR. For each candidate row, check Headers for URL, method and status, Payload for the marker or partial text, Initiator for the calling code, and Response or Preview for what the server returned.
  5. Click Send once. Compare the request and response with those from typing. If filtering hides traffic, switch to All. For a WebSocket connection, select its row and inspect Messages. Multiple messages can share the same connection. For supported streaming requests, also look for EventStream.
  6. Write a conclusion tied to the inspected traffic. Keep cookies, authorization headers, and real chat content out of shared screenshots or captures. Chrome DevTools Network reference
Sample finding. “When I typed, a request returned 200 and its readable payload contained my partial marker. This confirms the browser sent draft text to that endpoint during my test. The browser capture alone does not reveal whether the endpoint invoked a model, retained the text, or passed it to another service.”

If the payload is unreadable or the marker is absent, record the observation as inconclusive for that request. Backend traces or product documentation can establish what the receiving service does next.

07 · Real localhost requests in DevTools

Use Python 3 and the same HTML file. The server handles actual browser requests on your computer and returns scripted responses. The lab uses no external model, credentials, or packages.

  1. Download this HTML with the filename prompt-engineering-browser-to-ai.html.
  2. Copy the code below into demo-server.py in the same folder.
  3. Open a terminal in that folder and run py -3 demo-server.py on Windows, or python3 demo-server.py on macOS or Linux.
  4. Open http://127.0.0.1:8765/?lab=1, then open Network → Fetch/XHR and filter by /lab/. Try each mode above. Inspect Payload and compare the 200 responses for /lab/activity, /lab/draft and /lab/chat.
  5. In the chat request, inspect Response after the stream finishes. The demo uses newline-delimited JSON and sends several events within one HTTP response. Stop the server with Ctrl+C.
Show the complete Python server

from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
from pathlib import Path
from urllib.parse import urlsplit
import json
import time

PAGE = Path(__file__).with_name("prompt-engineering-browser-to-ai.html")


class Lab(BaseHTTPRequestHandler):
    def reply(self, status, content_type, body):
        self.send_response(status)
        self.send_header("Content-Type", content_type)
        self.send_header("Content-Length", str(len(body)))
        self.send_header("Cache-Control", "no-store")
        self.end_headers()
        self.wfile.write(body)

    def do_GET(self):
        if urlsplit(self.path).path != "/":
            self.send_error(404)
            return
        self.reply(200, "text/html; charset=utf-8", PAGE.read_bytes())

    def do_POST(self):
        routes = {"/lab/activity": "event", "/lab/draft": "draft",
                  "/lab/chat": "prompt"}
        field = routes.get(self.path)
        if field is None:
            self.send_error(404)
            return
        if self.headers.get_content_type() != "application/json":
            self.send_error(415)
            return
        try:
            size = int(self.headers.get("Content-Length", "0"))
            if not 0 < size <= 16000:
                self.send_error(413)
                return
            data = json.loads(self.rfile.read(size))
            if not isinstance(data, dict) or not isinstance(data.get(field), str):
                raise ValueError("Expected an object with a text field")
        except (ValueError, UnicodeError):
            self.send_error(400)
            return

        if self.path != "/lab/chat":
            self.reply(200, "application/json", b'{"received":true}')
            return

        # The server flushes simulated events. No model or external service runs.
        self.send_response(200)
        self.send_header("Content-Type", "application/x-ndjson")
        self.send_header("Cache-Control", "no-store")
        self.end_headers()
        events = [
            {"type": "start"},
            {"type": "delta", "text": "Mock response. "},
            {"type": "delta", "text": "The server received your submitted prompt."},
            {"type": "done"}
        ]
        try:
            for event in events:
                self.wfile.write((json.dumps(event) + "\n").encode())
                self.wfile.flush()
                time.sleep(0.22)
        except (BrokenPipeError, ConnectionResetError):
            return


if __name__ == "__main__":
    if not PAGE.is_file():
        raise SystemExit(f"Put {PAGE.name} in the same folder as demo-server.py.")
    print("Open http://127.0.0.1:8765/?lab=1", flush=True)
    with ThreadingHTTPServer(("127.0.0.1", 8765), Lab) as server:
        try:
            server.serve_forever()
        except KeyboardInterrupt:
            pass

Direct generationThe prompt, any supplied context, and patterns learned during training“Explain RAG to a beginner.”
Supplied contextThe text or file content provided to the model“Summarize the attached policy excerpt.”
Web search toolResults or pages fetched by a search-enabled system“Find the current documentation for this API.”

09 · Finding the right evidence, in order

Example question. “Who approves production access under the current policy?” The lab uses three fictional documents.

Before the question

Load and parse→Split into passages→Index with metadata

Store passage text with source, section, version, effective date, status and access metadata. An index may use keywords, embeddings, or both.

  1. Interpret the question. Extract the entity production access, the requested fact approvers, and the freshness requirement current policy.
  2. Enforce access and scope. Limit candidates to sources the requester may read. Use trusted metadata to scope by policy type, applicable system and effective version when available.
  3. Retrieve candidate passages. Keyword matching finds exact phrases or IDs. Semantic search finds related wording, such as “live environment privileges.” A hybrid search can combine them.
  4. Rank and select. Check that the passage answers the question directly and comes from an applicable, authoritative version. A retired policy can score highly on text similarity.
  5. Build grounded context. Supply the selected passage, its source identifier, the question, and instructions to cite claims and report missing evidence.
  6. Generate and verify. Check the cited text against each answer claim. When evidence is missing or active sources conflict, state the uncertainty. Retrieval quality and factual support need separate checks.

10 · Prompt engineering practice

Compare “Who approves access?” with a prompt that names the system, effective version, source boundaries and expected output. Use only the fictional passages above.

Question
Who must approve production access under the current policy?

Evidence
[ACCESS-2024 §3 | retired] Production access requires team lead approval.
[ACCESS-2026 §4 | current] Production access requires both the application
owner and Information Security to approve.
[ONBOARD-2026 §2 | current] Sandbox access requires a team lead’s approval.

Use evidence marked current and applicable to production access.
Give one sentence with the approvers and cite the policy ID and section.
If no current applicable passage supports the answer, say so.
If current applicable passages conflict, describe the conflict.
Expected answer and test variation

“The application owner and Information Security must both approve production access [ACCESS-2026 §4].” Remove ACCESS-2026 and run again. Expected result is an explicit statement that the provided evidence does not establish the current production-access rule. Compare each claim with its cited passage.

A well-specified prompt helps the model use available context. Evaluate retrieval separately by checking whether the right passage reached the model in the first place.

Three checks for a grounded answer

  1. Retrieval. Did the current, applicable source reach the model?
  2. Answer. Did the response include both approvers, with no unsupported additions?
  3. Citation. Can a learner open the cited section and point to the exact sentence that supports the claim?

Interview Q&A

Can a browser trace prove an LLM ran?

It can show a request and response visible to the browser. To verify a backend model call, correlate a request ID with authorized server logs or model instrumentation.

Why debounce a draft sync?

A debounce restarts its timer on each edit and sends after a pause, reducing traffic during bursts. This choice also delays synchronization.

Why can relevant text still lead to a wrong answer?

A passage can match the topic while covering the wrong version, scope or date. Check authority and claim-level support.

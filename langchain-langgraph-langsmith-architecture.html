1. Understand the three roles

Imagine an internal policy assistant. A learner asks, “Who approves production access?” The application must find the policy, supply context to a model, decide what to do when evidence is missing, and show developers how the request behaved.

TechnologyWhat it providesExample responsibility
LangChainReusable model, prompt, tool and retrieval interfaces, plus agent helpers.Build the model request using the retrieved policy and parse the response.
LangGraphStateful graph orchestration through nodes, edges and execution state.Route to an answer step when evidence exists, or to a clarification step otherwise.
LangSmithTracing, debugging and evaluation capabilities, with optional deployment products.Inspect the retrieved evidence, model call, errors and final output for a request.

The current LangChain create_agent helper uses LangGraph underneath. You can also compose LangChain components directly or implement a custom LangGraph workflow. LangSmith can instrument either approach and can trace other frameworks through supported integrations.

Execution path

The backend invokes application code. A graph or agent decides which steps run and when.

Observation path

Configured instrumentation sends run information to LangSmith so you can inspect and evaluate behaviour.

2. Combined architecture

The backend is your FastAPI, Flask, Lambda, container or other application. It authenticates the caller, invokes the workflow and returns the result. Model credentials and tool permissions belong to the execution environment.

  1. The application starts a graph run with a question and an authorized thread identifier.
  2. A node calls a retriever or model through its integration. LangChain interfaces can implement these node internals.
  3. The graph merges the node’s state update and follows the selected edge.
  4. A configured checkpointer saves execution state. A configured tracer sends run details to LangSmith.
  5. The application returns the answer and source references.
A checkpoint database, a retrieval index and LangSmith trace storage have different roles. The application chooses and configures each one.

4. LangGraph architecture

A graph represents execution as named nodes connected by edges. Each node receives state and returns an update. A conditional edge chooses the next node from the current state.

Building blockMeaningExample
State schemaThe fields available to the workflow.question, context, source and answer.
NodeA function performing one step.Retrieve a passage or draft an answer.
EdgeA transition between steps.Retrieve → Answer.
Conditional edgeA routing decision based on current state.Evidence present → answer, otherwise clarify.
ReducerDefines how updates to a state field combine.Use an appropriate message reducer when retaining message history.
CheckpointerPersists snapshots for an execution thread.Resume a workflow with the same authorized thread_id.
InterruptPauses execution for external input.Wait for a reviewer to approve a proposed action.
StorePersists application-defined data across threads.An authorized user preference or long-lived fact.

The sample uses replacement-style fields. A new question replaces the prior question in that state. A conversation agent can instead use a message-aware schema and reducer to retain messages deliberately.

Configure persistence to support pause and resume. A production checkpointer must survive process restarts. The lab’s InMemorySaver keeps checkpoints only in its running Python process.

5. LangSmith architecture

A trace groups the runs associated with an application request. A graph run can contain node runs, a retrieval step, a prompt and a model call. Instrumentation determines which details are recorded.

ConceptPurposeExample
RunOne recorded operation.A model call or retrieval function.
TraceA related hierarchy of runs.One complete policy-assistant request.
Thread/session groupingGroups related requests for inspection.Several turns in one conversation.
DatasetA repeatable collection of examples.Questions with expected answer facts and source references.
EvaluatorChecks output against a criterion.Correct approver, source support or expected route.
ExperimentResults for one application version on a dataset.Compare prompt version A with prompt version B.
Online evaluationScores selected live interactions.Track answer relevance on production traffic.

Model usage and estimated cost depend on what the provider and tracing integration report and how model pricing is configured. A trace can contain a scripted function with no model-token usage at all.

LangSmith also offers deployment capabilities. In this tutorial the application runs locally and sends optional telemetry to LangSmith. Hosting the application through LangSmith Deployment is an additional architecture choice.

7. Know where each kind of data belongs

DataTypical ownerLifecycle
Prompt and model messagesApplication and model adapter.Built for each invocation, with selected history.
Graph execution stateGraph runtime and configured checkpointer.Scoped to an authorized thread and its execution history.
Long-lived user factsApplication store.Retained under the application’s access and retention rules.
Document chunks and embeddingsRetrieval index or vector store.Updated when source documents are re-indexed.
Original documentsSource repository or object store.Authoritative source content and versions.
Traces and evaluation resultsLangSmith or another configured backend.Recorded according to tracing, privacy and retention settings.

Preparation flow for a vector-backed RAG system

Source documents are loaded, split into passages, embedded and indexed. At query time, an authorized retriever searches the index and returns passages. The graph uses those passages as context for generation.

Thread identity

Give each conversation or workflow an appropriate thread identifier. Validate that the caller is allowed to access it. Use a separate namespace or application record for long-lived preferences when the design needs cross-thread memory.

Restart behaviour

An in-memory checkpointer is convenient for a classroom run. A persistent backend, such as a supported database checkpointer, is needed when the workflow must resume after a process restart.

8. Model-free Python architecture lab

Create policy_architecture.py with the complete listing below. Install the packages once. The default lab uses an in-memory policy search and a deterministic scripted response. It exercises actual LangChain composition and LangGraph routing after installation.

Windows PowerShell setup

mkdir lang-architecture-lab
cd lang-architecture-lab
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade langchain-core langgraph langsmith
$env:LANGSMITH_TRACING = "false"

Use a Python version supported by the installed packages. On Ubuntu, create the environment with python3 -m venv .venv, use ./.venv/bin/python and set export LANGSMITH_TRACING=false.

from typing import TypedDict

from langchain_core.messages import AIMessage
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnableLambda
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import END, START, StateGraph


class PolicyState(TypedDict):
    question: str
    context: str
    source: str
    answer: str


POLICY = (
    "Production access requires manager approval and platform operations "
    "approval. Temporary access expires after 24 hours."
)

prompt = ChatPromptTemplate.from_messages([
    ("system", "Answer from the supplied policy evidence."),
    ("human", "Question: {question}\nPolicy evidence: {context}"),
])


def scripted_model(prompt_value):
    """Deterministic classroom response, with no external model call."""
    text = str(prompt_value.to_messages()[-1].content)
    if "manager approval and platform operations approval" in text:
        return AIMessage(content=(
            "Manager approval and platform operations approval are required."
        ))
    return AIMessage(content="The supplied policy has no matching evidence.")


answer_chain = prompt | RunnableLambda(scripted_model) | StrOutputParser()


def retrieve(state: PolicyState):
    words = state["question"].lower()
    if "production" in words and "access" in words:
        return {"context": POLICY, "source": "policy-demo-v1"}
    return {"context": "", "source": ""}


def route(state: PolicyState):
    return "answer" if state["context"] else "clarify"


def answer(state: PolicyState):
    text = answer_chain.invoke({
        "question": state["question"],
        "context": state["context"],
    })
    return {"answer": text + " Source: " + state["source"]}


def clarify(state: PolicyState):
    return {"answer": "Please provide an approved policy for this question."}


builder = StateGraph(PolicyState)
builder.add_node("retrieve", retrieve)
builder.add_node("answer", answer)
builder.add_node("clarify", clarify)
builder.add_edge(START, "retrieve")
builder.add_conditional_edges("retrieve", route, {
    "answer": "answer", "clarify": "clarify",
})
builder.add_edge("answer", END)
builder.add_edge("clarify", END)
graph = builder.compile(checkpointer=InMemorySaver())

if __name__ == "__main__":
    tests = [
        ("policy-101", "Who approves production access?"),
        ("policy-102", "Where is visitor parking?"),
    ]
    for thread_id, question in tests:
        config = {"configurable": {"thread_id": thread_id}}
        result = graph.invoke({
            "question": question, "context": "", "source": "", "answer": "",
        }, config=config)
        print(result["answer"])
        saved = graph.get_state(config)
        print("Checkpoint source:", saved.values["source"] or "none")
.\.venv\Scripts\python.exe policy_architecture.py

Expected output

Manager approval and platform operations approval are required. Source: policy-demo-v1
Checkpoint source: policy-demo-v1
Please provide an approved policy for this question.
Checkpoint source: none

11. Extend the architecture for production

Human review

A graph can pause with interrupt() and resume using external input. Configure a persistent checkpointer and reuse the authorized thread ID. Put irreversible actions after the required approval and make retryable effects idempotent.

Storage and execution

Choose a persistent checkpoint backend, a document index and an application store according to the data lifecycles in Section 7. Implement deadlines, cancellation and bounded tool/model retries. Bound loops so a failed decision cannot continue indefinitely.

Evaluation

Create examples for a supported access question, missing evidence, an outdated policy, an unauthorized document and a failing tool. Record the expected route, source and key answer facts. Compare versions on the same examples before rollout.

FailureWhat to inspectLikely change
Wrong answerRetrieved context and rendered prompt.Repair retrieval or guidance, then re-evaluate.
Repeated graph stepsRoutes, state updates and stop conditions.Add a bounded retry/iteration rule.
Lost state after restartCheckpointer configuration and thread IDs.Use persistent checkpoint storage.
Missing tracesTracing variables, workspace destination and key.Match the workspace setup and inspect telemetry failures.
Tool repeats a side effectRetry behaviour and operation identifiers.Make the operation idempotent and validate approval.
Access leakageUser-to-thread and document authorization.Apply access checks before using state or retrieved content.

12. Practice and architecture review

Trainer tasks

  1. Use the route simulator to show both branches before running Python.
  2. Change the policy approvers and the scripted response together. Explain the difference between a scripted demonstration and a model-generated answer.
  3. Add a review node after answer and before End. Store a review outcome in state.
  4. Change an input to force the clarification path. Inspect the resulting checkpoint and trace.
  5. Replace the scripted model with Bedrock and compare the output and recorded usage.
LangChain or LangGraph for a simple prompt-and-answer pipeline?

LangChain components can compose the prompt, model and parser. Introduce a custom LangGraph workflow when explicit branching, state and execution control are part of the requirement.

Does LangSmith require a LangChain application?

It supports multiple integrations and SDK instrumentation. Configure the appropriate tracing integration for the application.

Where does conversation memory come from?

The application deliberately chooses which messages or facts enter state, checkpoints or a store. A checkpointer persists the graph state associated with a thread.

Which component generates the natural-language answer?

The selected language model generates it. In the default lab a scripted callable supplies a deterministic teaching response.

13. Recap and official references

LangChain assembles the model-facing components. LangGraph controls stateful execution. LangSmith records and evaluates instrumented runs. The application owns user authentication, request handling and the storage choices around these libraries.
